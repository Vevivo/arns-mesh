# Security reports

This is an experimental preview, not an audited browser or a trustless name resolver.

If the repository's **Security → Report a vulnerability** option is enabled, use GitHub's private reporting flow. Otherwise ask the maintainer for a private reporting channel without posting the exploit, private endpoints, identities or credentials in a public issue. No private reporting email or response-time guarantee is claimed here.

Describe the affected version, trust boundary, minimal reproduction and observed impact. Redact operational details and do not test against someone else's running peer without authorization. If your own credential was exposed, revoke/rotate it before relying on repository-history cleanup.

Content signatures do not prove name freshness. Numeric-IP transport does not imply confidentiality. Read [architecture](docs/en/architecture.md), [privacy](docs/en/privacy.md) and [current acceptance status](docs/en/status.md).
